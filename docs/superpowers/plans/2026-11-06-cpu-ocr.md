# CPU OCR Service Implementation Plan

> Execution: inline, with test-first implementation and a final independent review.

**Goal:** Independently deployable CPU OCR service with per-request fast/accurate selection and real region streaming.

**Architecture:** Reuse sibling service transport/admin conventions. Keep engine, transactional store, orchestration and HTTP/MCP adapters separate. Model directories are explicit arguments, never request-dependent environment changes.

**Tech stack:** Python 3.11+, uv, MCP FastMCP, Starlette, Pydantic, Pillow, pytesseract, SQLite, uvicorn, httpx.

**Spec:** `../specs/2026-11-06-cpu-ocr-design.md`.

## Constraints and review focus

Preserve other projects and secrets. Accurate default on both transports. CPU-only. Existing preprocessing only. Review mixed-model concurrency, timeout/disconnect slot lifetime, upload/decode/output bounds, cache ownership and signatures, and partial-stream failures without successful cache entries.

## Decisions

The user clarified that mode choice belongs in requests sent by Citadel through HTTP or MCP. Both accept optional mode and default to accurate. The new folder is an isolated service; no existing repository is bulk-edited and no commits or remote publication are requested.

## Verification record

- Initial core and transport tests failed because the corresponding modules did not exist.
- Independent review found interrupted AnyIO cancellation draining and unhandled Pillow compressed-metadata ValueError. Both were reproduced, fixed and regression-tested; reviewer independently confirmed the cancellation repair.
- A timeout regression reproduced repeated cancellation of thread draining; shielded cleanup now also survives repeated direct cancellation and retains its CPU slot until completion.
- Native real OCR exposed pytesseract 0.3.13 Windows config quoting. Whitespace-free Windows model paths now use unquoted arguments; paths containing whitespace fail explicitly and are documented. POSIX paths use shlex.quote.
- A stateless MCP trial dropped progress notifications with the pinned SDK; retain peer-style sessions and document session affinity. The SDK's session-close SSE writer diagnostic is documented.
- `uv run --offline pytest -q -rs --tb=short`: 38 passed, two upstream dependency warnings (no skipped tests with binary/models installed).
- `uv run --offline ruff check src tests`: all checks passed.
- `docker compose --env-file NUL config --quiet`: passed using a throwaway validation token; no environment files read. Docker daemon is stopped, so image build remains unverified.
- Real screenshot smoke used a temporary local uvicorn server: both HTTP model requests succeeded, omitted mode selected accurate, two-region SSE completed, MCP fast request succeeded and reused the owned mode-specific cache. Results are retained in `.output/screenshot-service-results.json`; the smoke server was shut down.
